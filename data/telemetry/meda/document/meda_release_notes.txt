This document, release_notes.txt, contains release notes and errata
concerning the Mars2020 MEDA archives. It is updated with each release of 
MEDA data.

Section A of this document contains an entry for each MEDA release with
general information about the contents of the release, in order from newest
to oldest. Updates to previously released files are reported in these
entries, along with any known errata.

Section B of this file contains general notes, if any, concerning the archive
as a whole.

Some data after sol 1723 are not available at the time of release, due to 
downlink latencies during the solar conjunction. They caused the reception 
of the data on Earth to occur several weeks after the data acquisition on 
Mars, and outside the scope of this release time range. 

The missing data will be added to the next release.

Products from previous releases have been revised to include the following 
updates:

- Pressure data updates:

In previously released data, derived data pressure was based on what was 
considered the most reliable calibrated barocap for a particular time range. 
This was either barocap 2 or 3 from the pressure calibrated data products.
However, this caused some data inconsistencies. Because of this, derived 
data have been updated to always use barocap 3.

However, under some environmental conditions, barocap 3 can have 
discontinuities. When this happens, data from barocap 2 in the pressure 
calibrated data products should be checked by the user.

Since humidity data processing depends on pressure derived data, humidity 
data products have also been updated.

Products from previous releases have been revised to include
the following updates:

- TIRS data updates:

The values of broadband longwave radiation from the sky (dLW in the DER file)
have been updated, taking into account typical emission spectra for the sky
instead of assuming a model of black-body radiation and Stefan-Boltzmann-type
emission. The associated uncertainty was also updated according to the new
calculus. 
 
Status flags in partially processed files are now correctly updated.

TIRS measurements used for inflight calibration removed from calibrated and
derived data products.

New calculation to estimate the channels responsivity degradation for the
different sols. A linear interpolation between sols is performed, using for this
the results of the different in-flight calibration campaigns.

Until now, the result of the initial in-flight calibration campaign (sols 70-91)
was being used to estimate channels responsivity degradation. The in-flight
calibration campaigns for sols 429-436, 503-506 and 589-592 have confirmed an
additional degradation associated with the increment of dust in the atmosphere.
This is the reason that motivates the new calculation. The change affects
calibrated and derived data products.

- Pressure data updates:

Applied drift correction to barocap pressure data in CAL (calibrated) files
after sol 168. Derived DER files are mostly unaffected, since the barocaps
corrected are not used for the generation of derived data products, with two
exceptions:

1) Sol 313, when one of the corrected barocaps was used, for the range
15:00:05.423 - 18:44:42.043 LMST.

2) Sols 168-170, when a pressure self-test check was performed iterating over
the transducers.

Humidity data processing depends on pressure derived data, which means that
humidity data products were updated for the sols noted above.

- Ancillary data updates:

Rover location and orientation data in DER_ANCILLARY data products are revised
using updated SPK SPICE kernels. This makes some small updates to wind sensor
data and RDS/TIRS flags.

- Skycam issues:

Due to a ground data processing issue, there are four skycam images with an
incorrect image acquisition time. These are:

WSM_0441_0706103604_000*_N0250000MEDA00000_0000LUJ*
WSM_0441_0706103741_000*_N0250000MEDA00000_0000LUJ*
WSM_0441_0706103881_000*_N0250000MEDA00000_0000LUJ*
WSM_0441_0706104019_000*_N0250000MEDA00000_0000LUJ*

Their current times are:

SCLK 706103604 / LMST 0441M16:11:03
SCLK 706103741 / LMST 0441M16:13:16
SCLK 706103881 / LMST 0441M16:15:32
SCLK 706104019 / LMST 0441M16:17:46

But their true image acquisition times should be:

SCLK 705725550 / LMST 0437M09:58:40
SCLK 705737572 / LMST 0437M13:13:41
SCLK 705746020 / LMST 0437M15:30:43
SCLK 706093472 / LMST 0441M13:26:41

This is expected to be fixed in a future release.

Temperatures in skycam images headers after sol 241 are still
incorrect. They are expected to be fixed for release 6.

Comments:

Products from previous releases have been revised to include
the following updates:

- Data gaps present in environmental EDRs from previous releases have
  been eliminated, filling them with the missing data.

- Rover location data in DER_ANCILLARY files regenerated using higher
  accuracy data from localiced SPK SPICE kernels.

- Humidity data updates:

  Calibration fine tuning plus pressure dependent compensation of
  humidity calibrated and derived data.

  Added uncertainty of relative humidity. This is given only for the
  first 10 sec of each measurement session.

  Added uncertainity of the humicap local temperature.

  Added VMR in humidity derived data (only when RH > 2.5%).

- TIRS data updates:

  Update of thermopile responsivity degradation values (all channels:
  IR1, IR2, IR3, IR4 and IR5). Results obtained from the analysis of
  the new in-flight calibrations, as well as from the use of a linear
  interpolation of the degradation value between sols (degradation
  values obtained from in-flight calibrations carried out on specific
  campaigns and sols).

  The responsivity of thermopile IR3 (for which it is not possible to
  run the in-flight calibration algorithm) has been assumed to be
  equal to the arithmetic mean of the degradations of thermopiles IR4
  and IR5.

  New values for the thermal calibration coefficients vs. operating
  temperature (all channels: IR1, IR2, IR3, IR4 and IR5). These
  coefficients are the result of the analysis of the different
  in-flight calibration sequences performed on Mars.

  Update of the mathematical model for the IR3 thermopile, including
  new radiative terms to model the internal structure of the TIRS.

  The retrieval of the atmospheric temperature@40m (IR2 channel) has
  been updated taking into account both the undesired spectral
  transmistance windows of the IR2 channel [Sebastian et al., 2020]
  and otherwise the shape of a typical emission spectrum of the
  atmosphere [Smith et al., 2006].

Wind data beyond sol 315 is not provided for now due to issues with
the wind sensor (see section B.4 of this file).

Temperatures in skycam images headers after sol 241 are still
incorrect, pending a future update.

Comments:

A bug in the generation of environmental EDRs may create some minor
data gaps in some of the data products. These data gaps may have the
consecuence that some values in the RDRs are out of range. This will
be fixed at the next release.

Added derived wind data, that contains data selected from the most
appropiate boom at the calibrated level, thus providing single
measurements of wind speed and direction. Spurious data are filtered
at this level.

Wind calibrated data have been reprocessed and redelivered. The reason
is that, previously, the data from both booms of the wind sensor were
filtered when one of them was in a transitory state (due to a change
in their operational temperature). In this release, the filtering is
done independently per boom, which makes more calibrated data
available when one boom is on a stable state while the other is on a
transitory state.

A new calibration of humidity data is in progress and will be available 
in the next release. Details will be provided in due course. 

After sol 241, skycam images raw temperature data in the headers are
byte-swapped with respect to the order used in previous sols. This
couldn't be compensated on time for the release, and it has the
consecuence that, after that sol, the calibrated temperature data in
the skycam images headers are incorrect. In particular:

- Labels INSTRUMENT_TEMPERATURE and INSTRUMENT_TEMPERATURE_COUNT in
  the .IMG data products

- The correspondent tags img:Device_Temperatures (both img:raw_count
and img:temperature_value) in the .xml labels.

******** SECTION B ********

1. MEDA Observations do not include sub-second precision in LTST values, causing 
MEDA measurements at 2Hz sampling to have repeated LTST values on consecutive data
points.

2. Some sensors data should not be used before their post-landing
activities were complete. These are:

- Humidity Sensor data before sol 63.

- Wind Sensor data before sol 36.

3. For a quick overview of MEDA data and measurement strategy, please
refer to the readme.txt file included in the bundle's root directory.

4. At the moment, wind data beyond sol 315 is not provided due to
certain damage to some components of the wind sensor, as a result of
harsh weather conditions. Recalibration to compensate for the missing
elements is ongoing.
